the idea

The same numbers, joined up differently

Every element in this compiler reduces to a short vector of numbers, and a step between two beats is a lerp between two of them. That single sentence is what the five additions had to respect – so none of them introduced a new kind of thing to draw. A hexagon is the four numbers a rectangle already carries, turned into a different path; a turned label is a position plus an angle; a curve is the waypoints a straight line would have used. The frame, the viewBox and the animation never learned that any of it exists.

Each pair below is real: the source on the left compiled to the drawing on the right, and the drawing is inline SVG taking its ink from this page – which is why it follows your theme.

Four outlines that are not rectangles, aimed with a word

A protocol message that is an arrow, a sensor that is a hexagon, a size comparison that is a triangle, a scatter marker. They share one slot with .round and .sharp, because a hexagon has no corner radius to argue about.

Which way a point aims is the point option, not a class of its own. A chevron aimed up is the same shape aimed differently, and a class per shape per direction would quadruple a list meant to stay closed – so eight orientations cost one word, and the closed list came out shorter than it went in.

box a "SYN seq=c"       at 0,0 {.chevron .tone-3}
box b "SYN+ACK ack=c+1" below a point left {.chevron}
box c "IDS"             right of a {.hex .tone-1}
box d ""                below c {.wedge .tone-4}
box e ""                right of d point up {.wedge}
box f ""                right of e {.cross .accent}

A label that reads bottom to top

A tall narrow element has room for a word only along its long side. The angle rides on the label's own position vector, so a turned label is carried and interpolated by the machinery that already moves an upright one.

box  fw "FIREWALL" at 0,0 h 1.5 {.tone-4 .turn}
box  sw "SWITCH"   right of fw gap 0.7
edge fw -> sw.left
text ax "True Positive Rate" left of fw {.turn}

A chart that is still boxes

bars expands while the source is parsed, into ordinary boxes named f-0, f-1, f-2. Nothing downstream learns a new element kind – which is why a brace spans three columns with no special handling anywhere.

The baseline carries .front. Drawing order puts edges before boxes, which is right for an arrow – a box should cover the line arriving at it – and wrong for an axis, which came out hidden behind every column and visible only in the gaps.

bars  f "20,19,17,12,11,10,9,9,8,7,6,5"
        ". i e 0 l o 1 / a 3 5 M" at 0,0 w 2 h 0.9
brace b1 over f-0,f-1,f-2 bottom "Bin 1"
brace b2 over f-3,f-4,f-5,f-6,f-7 bottom "Bin 2"

A frame to draw in, and a line through its points

roc@0.35 names a value in the plot's own units. It is resolved into an ordinary reference to the frame's edge once the block has been read, so nothing below that pass – the dependency walk, the layout – knows plots exist. .smooth passes through every waypoint, so the class never moves a line off what it was attached to.

plot roc "False positive rate" "True positive rate"
     at 0,0 w 1.8 h 1.4 x 0,1 y 0,1 step 0.2
edge roc@0,roc@0 -> roc@1,roc@1 {.muted .dashed}
edge roc@0,roc@0 -> roc@1,roc@1 via roc@0.03,roc@0.45
     roc@0.1,roc@0.72 roc@0.3,roc@0.9 {.smooth .accent}

One drawing, however often it appears

A vector asset used to be spliced once per placement. The base-rate figure in this lecture has ninety-six faces; they are two files now, embedded once each and referenced. Only assets with no internal stylesheet are shared – a reference is a shadow clone, and a stylesheet does not reach into one.

grid g image face-ok 8x3 at 0,0 cell 0.26 space 0.09
text n "one file, twenty-four times" right of g

the lecture

What thirty-six slides look like

Every label, address and title sentence is the wording of the original slide, typos included and marked as deliberate in the source. The arrangement is not the original's: these use the whole slide width, and what the slides carried as body text beside the drawing became prose under the figure. Three groups are one drawing that develops rather than three drawings – the home network, the firewall, the confusion matrix – same names, same places, different steps.

These are stills of the printed state, which is the last beat without the lecture-time emphasis. In the live view each one steps. Every card opens the ::: diagram block it was compiled from – verbatim, comments and working notes included, because that is the thing the figure actually is.

the rules

Ten rules for a figure a room can read

The grammar will compile a bad figure as happily as a good one. These are the rules the thirty-six were built against, written as instructions rather than principles: what to do, what the eye is doing that makes it work, and a wrong/right pair you can copy. The name for the second part is the Gestalt principles – a short list of things human vision does before you have decided to look at anything. You do not get to opt out of them. A figure either uses them or fights them.

Every drawing below is compiled from the source beside it, by the same compiler the lecture uses. The wrong ones are wrong on purpose and were built to be looked at: two of them here were quietly breaking a different rule until someone did.

1

Group by distance, not by label

Make the gaps inside a group visibly smaller than the gaps between groups. A factor of two is enough; a factor of three is unmistakable.

Proximity is the fastest grouping cue there is, and it fires before anyone reads a word. If your spacing says one thing and your labels say another, the spacing wins and the labels look like a mistake.

wrong 
box a "Switch"    at 0,0
box b "Router"    right of a gap 0.5
box c "Resolver"  right of b gap 0.5
box d "Webserver" right of c gap 0.5
right 
box a "Switch"    at 0,0
box b "Router"    right of a gap 0.25
box c "Resolver"  right of b gap 0.9
box d "Webserver" right of c gap 0.25
2

Enclose what a distance cannot say

Use container for a trust boundary, a network segment, a DMZ, a machine that holds several parts. Do not try to say it with a bigger gap.

Common region beats proximity. A line drawn around things binds them even when they are far apart, and even when something else sits between them. A container is only as visible as its members and re-fits when they move, so it needs no show of its own and no maintenance when the figure changes.

wrong 
box a "A" at 0,0
box b "B" right of a gap 0.3
box r "Router" right of b gap 1.6
right 
box a "A" at 0,0
box b "B" right of a gap 0.3
box r "Router" right of b gap 1.6
container home "Home network" over a,b pad 0.4 {.dashed}
3

Keep edges for relations

Draw an edge when two things are actually connected. When you only want to point at something, use a leader: -> target on a text.

Uniform connectedness is the strongest grouping cue of all – stronger than proximity, stronger than colour. An arrow used as a pointing finger claims a relationship that is not there, and the room will look for it.

wrong 
box  sw "Switch" at 0,0
text n  "learns MAC addresses" right of sw gap 1.2
edge n -> sw
right 
box  sw "Switch" at 0,0
text n  "learns MAC addresses" right of sw gap 1.2 -> sw {.small .muted}
4

One tone, one role, all the way through

Decide at the start of a lecture what each fill means, write it down, and do not reuse a tone for a second meaning in the same figure.

Similarity groups things that are nowhere near each other. Two boxes in the same tone are claimed to be the same kind of thing, and the claim is made across the whole figure whether you meant it or not. The four tones are color-mix over the page’s own inks, never fixed hues – which is why this row re-mixes itself in your theme rather than carrying a palette in from a slide deck.

classmeans
.tone-1infrastructure: switch, router, resolver, firewall
.tone-2a legitimate host or participant
.tone-3payload: packets, protocol fields, records
.tone-4the one thing this beat is about – a solid fill, so use it sparingly
.accentthe attacker and the attack traffic
.dimpresent in the picture, not part of this scene
.mutedscaffolding: grid lines, zone outlines, annotations

Two tones from the same slot on one element is a conflict the linter reports. .tone-4 with .accent is not a slot conflict but is still a mistake: the fill is the accent, so accent ink on it is invisible.

5

Let a step say what belongs together

Tag the elements of a beat and reveal the tag, rather than listing names.

Things that appear together are read as one thing – common fate. The tag makes the source say what the picture says, and it survives you adding a ninth element to the group. Both of these draw the same beat; only one of them still will after the next edit.

wrong 
step attack
  show e, e-web, reply1, reply2, note-spoof
right 
step attack
  show @attack

Most edges need no show at all. An edge is only as visible as its two ends, a container only as visible as its members, a text with a leader only as visible as what it points at. Reveal the boxes and the wiring follows.

6

Give a label a ground when it sits on a line

Any text that overlaps a line, a grid or a filled area gets a fill class and some pad. .paper is the one that knocks a hole in what is behind it.

Figure and ground. Type on top of a line is read as texture, not as words, and on a projector at the back of a room it is simply lost. This is also why .paper exists as a class at all: a box already defaults to it, but a free text has no ground until you ask for one.

wrong 
box sw "Switch" at 0,0
box rt "Router" right of sw gap 2.4
edge sw -> rt
text lbl "10.1.1.0/24" between sw,rt
right 
box sw "Switch" at 0,0
box rt "Router" right of sw gap 2.4
edge sw -> rt
text lbl "10.1.1.0/24" between sw,rt pad 0.12 {.paper .small}
 

…and where it sits inside its own room is four more words

.left, .right, .top and .bottom mean “as far that way as this element allows” – its inner edge, not its border. A tall element with a short label is what they are for.

With more than one line they move the block, so .bottom puts the last line on the inner edge. They apply to a box, a dot and a free text; an edge label takes .left / .right only, since it is carried at the middle of its line. A container's caption and a brace's label are placed by their own statement, so writing one of the four words there is an error rather than a class that quietly does nothing.

wrong 
box zone "TRUSTED" at 0,0 w 1.2 h 2.4 {.tone-2}
right 
box zone "TRUSTED" at 0,0 w 1.2 h 2.4 {.tone-2 .top}
7

Run edges on axes, and bend them once

Keep edges horizontal or vertical. When one has to get around something, give it one waypoint, not three. Let crossings happen at right angles.

Good continuation – the eye follows a line through a junction and gives up at a corner. Each bend is a place a reader has to re-acquire the line. The build helps: an edge more than a fraction off an axis but less than 4° off is warned about, because that is almost never intent.

wrong 
edge c0 -> x1 via c0.cx,c0.bottom+0.25
                  c0.right+0.4,c0.bottom+0.25
                  c0.right+0.4,x1.top-0.25
                  x1.cx,x1.top-0.25
right 
edge c0 -> x1 via c0.left-0.4,c0.cy
                  c0.left-0.4,x1.cy

Note what the right-hand version does not do: it writes no coordinates. Both waypoints are expressions over other elements, so the route survives the figure being redrawn – and because the second takes its height from the target, the final approach is exactly horizontal by construction rather than by arithmetic you would have to redo.

8

End an edge on an anchor, never inside a box

Name the side the arrow should arrive at – b.left, b.top – whenever the automatic choice is wrong. Separate two edges between the same pair with a fraction along the side.

An arrowhead that crosses a border reads as a mistake in the drawing, and it obscures both the border and itself. The arrow stops at the boundary and the boundary stays unbroken.

wrong 
box  eve "Eve" at 0,0 h 1.15
box  bob "Bob" right of eve gap 2.2 same as eve
edge eve -> bob "replay"
edge eve -> bob "forgery"
right 
box  eve "Eve" at 0,0 h 1.15
box  bob "Bob" right of eve gap 2.2 same as eve
edge eve.right:0.3 -> bob.left:0.3 "replay"  {.accent}
edge eve.right:0.7 -> bob.left:0.7 "forgery" {.accent}

The same as is load-bearing, and leaving it out is how this rule is usually got wrong: a fraction of two different heights lands at two different places, so the pair comes out very slightly skewed. The build says so by name – it is one of the two things the 4°-off-axis warning is written for.

9

Draw the fewest things that carry the argument

Cut anything that is not doing work. A server does not need drive bays, a compromised host does not need a biohazard symbol, a person does not need a face unless the figure is about people.

Prägnanz – vision settles on the simplest reading available, so every mark you add is a mark someone has to rule out. Before you add an element, ask which beat it belongs to. If the answer is “none”, it is decoration.

10

No shadows, no free colours, no rotation for effect

Stay inside the closed vocabulary.

A shadow is a depth cue in a drawing that has no depth: it adds a second edge to every shape and buys nothing. The vocabulary has none, and that is not an oversight. .turn is for a label with no room to be horizontal – a firewall bar, a matrix row, an axis title – not a way to make a figure look busy. And a fixed hue imported from a slide deck works on exactly one background, which is the argument rule 4 already made.

steps and tags

A beat is the same layout, evaluated again

A step is not a transform applied to a finished picture. It is another evaluation of the same layout with different inputs, so an arrow stays attached to a box that walks away – the arrow never stored a coordinate, it stored “the right edge of px”. The build resolves every beat and hands the browser the numbers; the runtime interpolates between two of them and does no layout at all.

Both figures below are live. They carry the same runtime a projected lecture ships, and their beats ride the same counter a reveal does – which is why stepping backwards costs nothing.

Four beats, and one line that reveals three things

The order from the checklist further down: the stage, the normal case, the disturbance, the consequence. Press through it.

::: diagram {unit=160x54}
# The four-beat order from figure-design.md on the smallest scene that still
# carries an argument. Nothing here is revealed element by element: the
# disturbance is one line, `show @attack`, and the wire and the forged answer
# come with it because an edge is only as visible as its ends.
box  a  "A"      at 0,0 {.tone-2}
box  sw "Switch" right of a gap 1.2 {.tone-1}
box  b  "B"      right of sw gap 1.2 {.tone-2}
edge a -- sw {.muted}
edge sw -- b {.muted}

text q "who has 10.1.1.5?" above sw gap 0.7 pad 0.1 {.small .paper @ask}
text r "10.1.1.5 is at bb:bb" below b gap 0.6 pad 0.1 {.small .paper @answer}

box  e  "E" below sw gap 1.15 {.accent @attack}
edge e.top -- sw.bottom {.accent @attack}
text s "10.1.1.5 is at ee:ee" right of e gap 0.6 pad 0.1 -> e {.small .paper .accent @attack}

step ask
  show @ask
  emph a
step answer
  show @answer
  emph b
  calm a
step spoof
  show @attack
  emph e
  calm b
step redirected
  style r {.dim}
  emph e, s
:::

The third beat is show @attack – one line. It reaches E, the wire to the switch and the forged answer, because all three carry @attack in their attribute tail. Adding a fourth element to the group is an edit at that element, not an edit somewhere else in the file, and that is the whole reason tags replaced a group statement. Note what carries no show at all: an edge is only as visible as its two ends, so the wire arrives with E without being named. calm is doing the quiet work – it drops the emphasis from the previous beat and dims it, so the picture never ends up with four things shouting at once.

A box that walks away, and everything that follows it

One step, one move. Watch what nobody had to write down.

::: diagram {unit=160x54}
# Nothing here stores a coordinate. The two arrows were written as "from cl"
# and "to sv", and the outline as "over cl,px" - so when the proxy moves,
# they follow, and the outline re-fits around a row instead of a column.
box cl "Client" at 0,0 {.tone-2}
box sv "Server" right of cl gap 3.0 {.tone-1}
box px "Proxy"  below cl gap 1.0 offset 1.0,0 {.tone-4}
edge cl -> sv "direct" {#direct .dashed .muted}
edge cl -> px {.muted}
edge px -> sv {.muted}
container zone "client side" over cl,px pad 0.36 {.dashed .muted}

step interpose
  hide direct
  move px to between cl,sv
  emph px
:::

The two arrows were written as “from cl” and “to sv”, and the outline as “over cl,px”. So when the proxy moves onto the path, the arrows follow it and the outline re-fits around a row instead of a column – because the layout is solved again, not nudged. hide direct takes the bypassed arrow away in the same beat; without it the label of a line nobody can see any more sits across the box that replaced it. And move takes to for one element or by for a set: move @tag to … is refused, because it would stack the whole set on one point.

What print gets is the last beat without the emphasis – not the union of all of them. Everything shown and never hidden is in the last beat anyway, so the two readings differ only where the author wrote hide, and there the last beat is the one that means “the finished picture”. That is also what a reader with no JavaScript sees, because the static attributes in the emitted SVG are the print state. The live views carry a second viewBox, the union of every beat, or an element walking in from outside the frame would be clipped for the whole of its journey.

the order, and the walls

A figure with steps is an argument, not a slideshow

Beats are not a way to reveal a picture slowly. They are the order the argument is made in, and this one works almost every time.

beat 1

The stage

Everything that is just true: the topology, the axes, the participants. One beat, no emphasis.

beat 2

The normal case

What happens when nothing is wrong. This is what the attack will be measured against.

beat 3

The disturbance

The attacker, the failure, the exception. This is the beat that earns .accent and emph.

beat 4

The consequence

The defence, the result, the number. Often calm on what came before, so the last beat is not four things shouting at once.

Print is the last beat without the emphasis – not the union of all beats. So the last beat has to be a picture that makes sense on paper, standing alone. If it is not, you have one beat too few. Stepping backwards costs nothing, because every beat is recomputed from the counter, which is what makes hide as usable as show.

before a figure is finished

Ten things, checkable mechanically

  1. node lint.js <source.md> is clean. No warnings talked past.
  2. node build.js <source.md> prints no [diagram] warning, or the source carries a comment saying why the remaining one is deliberate.
  3. No edge runs at a slight angle. The build says so; do not silence it by nudging – align the elements.
  4. Every label that overlaps a line or a fill has a fill class of its own.
  5. Every arrowhead lands on a border, none inside a box, none two-on-a-line.
  6. No tone carries two meanings in one figure, and none contradicts the table in rule 4.
  7. Each beat is one idea. Read the step names out loud in order: they should sound like an argument.
  8. The last beat is a sensible handout picture on its own.
  9. Opened in the browser and cycled through all seven themes with A: nothing disappears, nothing goes unreadable. The two phosphor modes are the strict ones.
  10. node test/run.mjs framing passes. It measures the slack on all four sides of every figure, and it is the only check that catches a picture which is correct but not centred in its own frame.

what it deliberately cannot do

Knowing the walls saves the time spent walking into them

No free colours

Four tones, plus .accent and .muted. If you need a fifth distinction, use shape (.hex, .chevron, .wedge, .cross, aimed with point) or family (.mono, .serif) – and ask first whether the figure is doing too much.

No automatic routing

Edges are straight segments through the waypoints you write. Nothing steps around a box for you, and nothing fans out parallel edges – that is what the :0.3 / :0.7 fractions are for.

No automatic line breaking

A label breaks where you write \n, and nowhere else.

No shadows, no gradients

Drawing order is fixed too – containers, images, braces, edges, then boxes, dots and texts – with one way out: .front moves an edge in front of the boxes. Right for an axis, wrong for an arrow, so it is opt-in.

No arbitrary rotation

.turn turns a label 90°, and point aims a chevron or a wedge at one of the four compass directions. Nothing rotates to an arbitrary angle.

No cylinder, no cloud

The outlines are the rectangle, the circle, the hexagon, the two chevrons and the wedge. A database is a .round box in the tone you gave storage; a cloud is a box labelled Internet. If a shape is genuinely load-bearing, it is an SVG asset and image places it.

Text width is estimated

There is no browser at build time, so the estimate is tuned slightly generous – a box a little wider than its text reads as designed, a box narrower reads as broken. Where it matters, give an explicit w.

No constraint solver

Positions are expressions over other positions, resolved by one topological walk. A circular arrangement is an error naming the line, which is the whole point: a solver would render it plausibly wrong.
