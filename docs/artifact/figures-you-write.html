psi-slides · ::: diagram

Figures You Write

A figure in a psi-slides lecture is a dozen lines of text you write inside the lecture’s Markdown file, in a small language called ::: diagram. The build – the one command that turns that file into slides – reads those lines, works out where every part belongs, and writes one drawing into the finished slide. There is no drawing tool to open, and the file you edit stays plain text you can read.

start here

One figure, a line at a time

One figure, built up in six stages. Each stage adds a single idea and shows the whole figure so far: the source, with the new lines marked, and the drawing that source produces. Everything later on this page is built out of these six pieces.

How a line is put together

Every statement has the same shape. Not every slot is filled every time – most lines use three or four of them – but they always come in this order.

 box   sw   "Switch"   right of a gap 0.4   w 1.2   {.tone-1 #main @net}
└─┬─┘ └┬─┘ └───┬────┘ └────────┬─────────┘ └──┬──┘ └─────────┬──────────┘
  │    │       │               │              │              └── tail: classes, an id, tags
  │    │       │               │              └── options: size, padding, routing
  │    │       │               └── placement: where it goes, relative to something else
  │    │       └── label: what the reader sees. Optional, and "" is a legal empty one
  │    └── name: how later lines refer to this element. Never drawn
  └── statement: what kind of thing this is

Placement is the slot that makes the rest work. Only the first element in a figure gives a position outright; everything after it is placed against something already there, so the figure is a chain of relations rather than a list of coordinates. That is what lets a drawing survive being rearranged, and it is also why an arrangement that refers back to itself is reported as an error on the line that caused it.

Eight things the shape above does not tell you

Everything is in the figure’s own units

The block opens with ::: diagram {unit=170x56}, which sets how many pixels one unit is across and down. After that every number – a gap, a width, a nudge – is in units, so a figure keeps its proportions whatever size it is drawn at. One unit is meant to be about one box wide.

Three different marks share one pair of braces

In the tail, .something is a class, #something is a name you are giving the element, and @something is a tag that puts it in a group. A box is usually named in its second word instead; the # form is there for the statements that have no name slot, such as edge.

A coordinate can be another element’s coordinate

Written sw.right, sw.cx, sw.top and so on, optionally with a nudge: sw.right+0.4. A pair separated by a comma is a point: sw.right+0.4,sw.cy. This is what keeps a route attached to what it was drawn against.

A fraction slides an endpoint along a side

eve.right:0.3 is three tenths of the way down Eve’s right-hand side. Two edges between the same pair at :0.3 and :0.7 run parallel instead of on top of each other.

gap and space are not the same word

gap is the distance to the element you are placing against. space is the distance between the bars of a chart or the cells of a grid. They were one word once, and a gap written before the placement meant something different from one written after it, with no error either way.

same as copies the size, not the position

box bob "Bob" right of eve gap 2.2 same as eve places Bob relative to Eve and gives him Eve’s width and height. Leaving it out is how two parallel edges end up slightly skewed, because a fraction of two different heights lands at two different places.

Steps are indented under the beat they belong to

A step line names the beat; the operations that make it up are indented beneath it. There are seven: show, hide, move, emph, calm, style and label.

A line starting with # is a comment

Anywhere inside the block. It is worth using them: the reason a figure is arranged the way it is rarely survives in the arrangement itself.

Two boxes, and a name nobody sees

Every line has the same four parts: what kind of thing this is, what it is called, what it says, and where it goes. Here box is the kind and "Client" is the label. cl is the name, and the name is never drawn – it is there so that later lines can point at this box. at 0,0 is the position, and it is the only position in the whole figure that names a number rather than another element.

::: diagram {unit=170x56}
box cl "Client" at 0,0
box sv "Server" right of cl gap 1.4
:::

An edge names its two ends

The new line says which boxes are connected. It does not say where the line runs. The build works that out from where the boxes ended up, and works it out again whenever anything moves. That is why a figure written this way survives being rearranged: no line here stores a coordinate that could go stale.

::: diagram {unit=170x56}
box cl "Client" at 0,0
box sv "Server" right of cl gap 1.4
edge cl -> sv
:::

Positions refer to other positions

Only the first box needs at. Everything after it is placed against something already on the drawing, with right of, below or between, and a gap measured in the figure’s own units. Because each position points at an earlier one, the build can work the whole figure out in a single pass, following the chain. An arrangement that refers back to itself is reported as an error naming the line that caused it.

::: diagram {unit=170x56}
box cl "Client" at 0,0
box sv "Server" right of cl gap 1.4
edge cl -> sv
box log "Log" below sv gap 0.9
edge sv -> log
:::

The tail holds classes, an id and tags

Anything in braces at the end of a line describes the element rather than placing it. The words beginning with a dot are its classes, and they set how it looks; .tone-1 and its neighbours are fills. There are thirty-eight classes in ten groups, and only one class from each group can apply, so two settings that contradict each other never both take effect. The fills are mixed from this page’s own text and background colours instead of being fixed values, which is why these drawings follow your theme rather than bringing one of their own.

::: diagram {unit=170x56}
box cl "Client" at 0,0 {.tone-2}
box sv "Server" right of cl gap 1.4 {.tone-1}
edge cl -> sv
box log "Log" below sv gap 0.9 {.tone-3}
edge sv -> log
:::

Words that are not in a box

A text is a label with no outline around it. The -> sv at the end draws a leader: a thin line from the note to the thing it describes. A leader is not an arrow, and the difference matters: an arrow claims that two things are connected, and a reader who sees one will go looking for the connection.

::: diagram {unit=170x56}
box cl "Client" at 0,0 {.tone-2}
box sv "Server" right of cl gap 1.4 {.tone-1}
edge cl -> sv
box log "Log" below sv gap 0.9 {.tone-3}
edge sv -> log
text n "TLS ends here" right of sv gap 1.2 -> sv {.small .muted}
:::

A boundary around part of the figure

A container outlines the members you name and re-fits itself when they move. It also takes its visibility from them. You never have to reveal it separately, and it cannot end up drawn around nothing.

::: diagram {unit=170x56}
box cl "Client" at 0,0 {.tone-2}
box sv "Server" right of cl gap 1.4 {.tone-1}
edge cl -> sv
box log "Log" below sv gap 0.9 {.tone-3}
edge sv -> log
text n "TLS ends here" right of sv gap 1.2 -> sv {.small .muted}
container dmz "DMZ" over sv,log pad 0.4 {.dashed .muted}
:::

That is the everyday vocabulary. The rest of this page is about using it well: ten rules for a figure a room can read at a glance, then what happens when a figure moves.

the rest of the tail

Ten groups of classes, and six more words

The six steps above use one class. This is the whole list, and it is short enough to read once. Classes are grouped by what they set, and only one from each group applies to an element, so a fill can never fight another fill. Anything not in the list is refused when the figure is built rather than ignored.

groupclasseswhat it sets
fill.tone-1 .tone-2 .tone-3 .tone-4 .clear .paperWhat the shape is filled with. .paper is the page background, which is what makes a label punch a hole in a line behind it; .clear is no fill at all.
ink.accent .mutedWhich colour the outline and the words take. .accent is the one strong colour on the page; .muted is lighter and thinner, for supporting apparatus.
stroke pattern.dashed .dottedA broken outline. Conventionally a boundary you can cross, or a thing that is not really there.
stroke weight.thick .bareA heavier outline, or none at all. .bare leaves the fill and the label with no border round them.
outline.round .sharp .hex .chevron .wedge .crossThe shape drawn. A hexagon, a chevron, a triangle and a cross are all the same four numbers as the rectangle, drawn along a different path.
arrowheads.no-head .both-headsOn an edge: a plain line with no arrowhead, or one at each end. The default is a single head at the end you wrote second.
weight.boldThe label in a heavier weight, for the one element a figure is about.
size.small .largeThe label one step down or up from the figure’s normal size.
family.mono .serif .handTypeface for the label: fixed-width for addresses and code, the reading face, or that face in italic for something written in beside the drawing.
fitting.fit .shrinkWhat to do when the label does not match the box. .fit grows or shrinks the type to fill a width you gave; .shrink only ever shrinks. Both need a width to fit into.
label across.left .rightPush the label to one side of the room its element gives it.
label down.top .bottomThe same on the other axis. On an edge these four pick which side of the line the label sits on instead.

Size

w h r same as

A width and a height in the figure’s own units, a radius for a dot, or the size of another element copied wholesale. Leave them out and a box is as big as its label needs.

Nudging a placement

offset align

After right of a gap 0.4 you can add offset 0.2,0 to shift the result, or align left to keep the new element’s left edge flush with the one it was placed against. This align is part of a placement and takes one word.

Lining several elements up

align spread

Written on a line of their own, these are statements rather than placements: align y middle a, b, c gives b and c the vertical centre of a, and spread distributes a set evenly. The first element named is the one the others follow.

Routing an edge

via

edge a -> b via a.right+0.4,a.cy sends the line through the points you list before it arrives. A point can be written as another element’s coordinate plus a nudge, so the route survives the figure being rearranged.

Setting a base for everything

default

default box .tone-2 w 1.1 at the top of a block applies to every box in it, and an element’s own tail overrides it. The same lines in a diagram-defaults: key in the lecture frontmatter set the house style for every figure in the lecture.

Two of these share a word. align at the end of a placement keeps one edge flush with the element you placed against; align on a line of its own is a statement that hands one coordinate from the first element named to all the others. They are easy to tell apart in practice, because the statement always begins the line and names an axis.

the rules

Ten rules for a figure a room can read

The build will draw a bad figure as readily as a good one, so the rest is up to you. Each rule below has three parts: what to do, what the eye is already doing that makes it work, and a wrong and a right version in real source you can copy. The second part draws on the Gestalt principles, a short list of groupings human vision performs before you have decided to look at anything. A reader cannot switch them off, so a figure either uses them or fights them.

Every drawing below was produced from the source shown with it. The versions marked wrong are wrong on purpose, and worth a second look: nothing in the build can detect what they get wrong.

1

Group by distance, not by label

Make the gaps inside a group visibly smaller than the gaps between groups. A factor of two is enough; a factor of three is unmistakable.

Proximity is the fastest grouping cue there is, and it fires before anyone reads a word. If your spacing says one thing and your labels say another, the spacing wins and the labels look like a mistake.

wrong 
box a "Switch"    at 0,0 {.tone-1}
box b "Router"    right of a gap 0.5 {.tone-1}
box c "Resolver"  right of b gap 0.5 {.tone-1}
box d "Webserver" right of c gap 0.5 {.tone-2}
right 
box a "Switch"    at 0,0 {.tone-1}
box b "Router"    right of a gap 0.25 {.tone-1}
box c "Resolver"  right of b gap 0.9 {.tone-1}
box d "Webserver" right of c gap 0.25 {.tone-2}
2

Enclose what a distance cannot say

Use container for a trust boundary, a network segment, a DMZ, a machine that holds several parts. Do not try to say it with a bigger gap.

Common region beats proximity. An outline drawn around things binds them even when they are far apart, and even when something else sits between them – so a container overrules whatever your spacing happens to say.

wrong 
box a "A" at 0,0 {.tone-2}
box b "B" right of a gap 0.3 {.tone-2}
box r "Router" right of b gap 1.6 {.tone-1}
right 
box a "A" at 0,0 {.tone-2}
box b "B" right of a gap 0.3 {.tone-2}
box r "Router" right of b gap 1.6 {.tone-1}
container home "Home network" over a,b pad 0.4 {.dashed}
3

Keep edges for relations

Draw an edge when two things are actually connected. When you only want to point at something, use a leader: -> target on a text.

Uniform connectedness – two things joined by a line are read as one unit – is the strongest grouping cue of all, stronger than proximity and stronger than colour. An arrow used as a pointing finger claims a relationship that is not there, and the room will look for it.

wrong 
box  sw "Switch" at 0,0 {.tone-1}
text n  "learns MAC addresses" right of sw gap 1.2
edge n -> sw
right 
box  sw "Switch" at 0,0 {.tone-1}
text n  "learns MAC addresses" right of sw gap 1.2 -> sw {.small .muted}
4

One tone, one role, all the way through

Decide at the start of a lecture what each fill means, write it down, and do not reuse a tone for a second meaning in the same figure.

Similarity groups things that are nowhere near each other. Two boxes in the same tone are claimed to be the same kind of thing, and the claim is made across the whole figure whether you meant it or not. The row below shows the four tones and what each is for.

classmeans
.tone-1infrastructure: switch, router, resolver, firewall
.tone-2a legitimate host or participant
.tone-3payload: packets, protocol fields, records
.tone-4the one thing this beat is about – a solid fill, so use it sparingly
.accentthe attacker and the attack traffic
.dimstill on screen, but not part of what is being said now: full colour at a third of the strength. A step reaches for this through calm.
.mutedsupporting apparatus rather than subject matter: axes, leaders, grid lines, zone outlines. Drawn lighter and thinner, at full strength.

Two tones from the same group on one element contradict each other, and the linter (node lint.js) reports it. .tone-4 with .accent is not that kind of contradiction and is still a mistake: .tone-4 is already filled with the accent colour, so accent text on top of it cannot be seen.

5

Let a step say what belongs together

Give the elements of one beat a shared tag and reveal the tag, rather than listing their names. A beat is one press of the key that advances the slide; the section after this one shows two figures stepping through theirs.

Things that appear together are read as one thing. The tag makes the source say what the picture says, and it keeps saying it when you add a ninth element to the group. Both versions below draw the same beat today; after the next element is added, only the tagged one still will.

wrong 
step attack
  show e, e-web, reply1, reply2, note-spoof
right 
step attack
  show @attack

Most edges need no show of their own. An edge is only as visible as the two things it joins, a container only as visible as its members, a note with a leader only as visible as what it points at. Reveal the boxes and the lines that connect them appear with them.

6

Give a label a ground when it sits on a line

Any text that overlaps a line, a grid or a filled area gets a fill class and some pad. .paper is the one that knocks a hole in what is behind it.

Type printed on top of a line is read as texture rather than as words, and from the back of a room it is lost altogether. This is figure and ground, the oldest of the grouping effects. A box is filled with the background colour already; a text on its own has no fill until you ask for one, which is what .paper is for.

wrong 
box sw "Switch" at 0,0 {.tone-1}
box rt "Router" right of sw gap 2.4 {.tone-1}
edge sw -> rt
text lbl "10.1.1.0/24" between sw,rt
right 
box sw "Switch" at 0,0 {.tone-1}
box rt "Router" right of sw gap 2.4 {.tone-1}
edge sw -> rt
text lbl "10.1.1.0/24" between sw,rt pad 0.12 {.paper .small}
6 ·

Rule 6 continued: four words place a label inside its own box

.left, .right, .top and .bottom mean “as far that way as this element allows” – its inner edge, not its border. A tall element with a short label is what they are for.

With more than one line they move the block, so .bottom puts the last line on the inner edge. They apply to a box, a dot and a free text; on an edge all four name which side of the line the label sits on: .top or .bottom beside a horizontal edge, .left or .right beside a vertical one, and .turn stands the words on end beside it. Naming the pair that runs along the edge cannot move anything, so the build says so. A container’s caption and a brace’s label are placed by their own statement, so writing one of the four words there is an error rather than a class that quietly does nothing.

wrong 
box zone "TRUSTED" at 0,0 w 1.2 h 2.4 {.tone-2}
right 
box zone "TRUSTED" at 0,0 w 1.2 h 2.4 {.tone-2 .top}
7

Run edges on axes, and bend them once

Keep edges horizontal or vertical. When one has to get around something, give it one waypoint – a point you tell the line to pass through – rather than three. Let crossings happen at right angles.

Good continuation – the eye follows a line through a junction and gives up at a corner. Each bend is a place a reader has to re-acquire the line. The build helps: an edge that misses horizontal or vertical, but misses it by less than 4°, is reported as a warning, because a line that nearly lines up is almost never what anyone meant.

wrong 
box c0  "C0"  at 0,0 {.tone-3}
box dec "Dec" below c0 gap 0.5 {.tone-1}
box x1  "X1"  below dec gap 0.5 {.tone-3}
box p1  "P1"  right of x1 gap 0.9 {.tone-2}
edge x1 -> p1
edge c0 -> x1 via c0.cx,c0.bottom+0.25 c0.right+0.4,c0.bottom+0.25 c0.right+0.4,x1.top-0.25 x1.cx,x1.top-0.25
right 
box c0  "C0"  at 0,0 {.tone-3}
box dec "Dec" below c0 gap 0.5 {.tone-1}
box x1  "X1"  below dec gap 0.5 {.tone-3}
box p1  "P1"  right of x1 gap 0.9 {.tone-2}
edge x1 -> p1
edge c0 -> x1 via c0.left-0.4,c0.cy c0.left-0.4,x1.cy

The version marked right writes no coordinates at all. Both of its waypoints are given in terms of other elements, so the route still holds after the figure is rearranged; and because the second waypoint takes its height from the box the edge ends at, the final approach comes out horizontal without anyone having to work out a number.

8

End an edge on an anchor, never inside a box

Name the side the arrow should arrive at – b.left, b.top – whenever the automatic choice is wrong. Separate two edges between the same pair with a fraction along the side.

An arrowhead that crosses a border reads as a mistake in the drawing, and it obscures both the border and itself. The arrow stops at the boundary and the boundary stays unbroken.

wrong 
box  eve "Eve" at 0,0 h 1.05 {.accent}
box  bob "Bob" right of eve gap 2.2 same as eve {.tone-2}
edge eve -> bob "replay"
edge eve -> bob "forgery"
right 
box  eve "Eve" at 0,0 h 1.05 {.accent}
box  bob "Bob" right of eve gap 2.2 same as eve {.tone-2}
edge eve.right:0.3 -> bob.left:0.3 "replay"  {.accent}
edge eve.right:0.7 -> bob.left:0.7 "forgery" {.accent .bottom}

Leaving out same as, which gives one element the same size as another, is how this rule is usually got wrong. The fraction is measured along each box’s own side, so two boxes of different heights put the two ends at different heights and the pair comes out slightly skewed. The build warns about it: this is one of the two cases the off-axis warning in rule 7 exists for.

9

Draw the fewest things that carry the argument

Cut anything that is not doing work. A server does not need drive bays, a compromised host does not need a biohazard symbol, a person does not need a face unless the figure is about people.

Prägnanz – vision settles on the simplest reading available, so every mark you add is a mark someone has to rule out. Before you add an element, ask which beat it belongs to. If the answer is “none”, it is decoration.

10

No shadows, no free colours, no rotation for effect

Stay inside the list of classes the language gives you. There is no way to add to it.

A shadow is a depth cue in a drawing that has no depth: it adds a second edge to every shape and buys nothing. There is no way to ask for one. .turn is for a label with no room to be horizontal – a firewall bar, a matrix row, an axis title – not a way to make a figure look busy. And a fixed hue imported from a slide deck works on exactly one background, which is the argument rule 4 already made.

steps and tags

How a figure moves from one beat to the next

Each beat is the whole figure laid out again, with different inputs. Nothing is nudged, and nothing is animated on top of a finished picture. That is why an arrow stays attached to a box that walks away: the arrow never held a coordinate, it held “the right edge of px”, and that still points at the box wherever the box now is. The build works out every beat in advance and hands the browser the numbers to slide between.

Both figures below are live: they run exactly the code a projected lecture runs. Step forward and back with the arrows, or press play.

Four beats, and one line that reveals three things

The four-beat order set out lower down the page: the stage, the normal case, the disturbance, the consequence. Step through it.

::: diagram {unit=160x54}
# The four-beat order from figure-design.md on the smallest scene that still
# carries an argument. Nothing here is revealed element by element: the
# disturbance is one line, `show @attack`, and the wire and the forged answer
# come with it because an edge is only as visible as its ends.
box  a  "A"      at 0,0 {.tone-2}
box  sw "Switch" right of a gap 1.2 {.tone-1}
box  b  "B"      right of sw gap 1.2 {.tone-2}
edge a -- sw {.muted}
edge sw -- b {.muted}

text q "who has 10.1.1.5?" above sw gap 0.7 pad 0.1 {.small .paper @ask}
text r "10.1.1.5 is at bb:bb" below b gap 0.6 pad 0.1 {.small .paper @answer}

box  e  "E" below sw gap 1.15 {.accent @attack}
edge e.top -- sw.bottom {.accent @attack}
text s "10.1.1.5 is at ee:ee" right of e gap 0.6 pad 0.1 -> e {.small .paper .accent @attack}

step ask
  show @ask
  emph a
step answer
  show @answer
  emph b
  calm a
step spoof
  show @attack
  emph e
  calm b
step redirected
  style r {.dim}
  emph e, s
:::

The third beat is one line, show @attack. It reveals three things – E, the wire to the switch, and the forged answer – because all three carry @attack in their attribute tail. To bring a fourth element into the group you write the tag on that element; there is no line anywhere else in the file to change. Note what carries no show at all: the wire arrives with E, because rule 5 already covers it. Two of the beats end with a calm, which takes the emphasis off whatever the previous beat emphasised and dims it, so the picture never ends up with four things shouting at once.

A box that walks away, and everything that follows it

One beat, one move statement. Everything else in the figure follows on its own.

::: diagram {unit=160x54}
# Nothing here stores a coordinate. The two arrows were written as "from cl"
# and "to sv", and the outline as "over cl,px" - so when the proxy moves,
# they follow, and the outline re-fits around a row instead of a column.
box cl "Client" at 0,0 {.tone-2}
box sv "Server" right of cl gap 3.0 {.tone-1}
box px "Proxy"  below cl gap 1.0 offset 1.0,0 {.tone-4}
edge cl -> sv "direct" {#direct .dashed .muted}
edge cl -> px {.muted}
edge px -> sv {.muted}
container zone "client side" over cl,px pad 0.36 {.dashed .muted}

step interpose
  hide direct
  move px to between cl,sv
  emph px
:::

The two arrows were written as “from cl” and “to sv”, and the outline as “over cl,px”. So when the proxy moves onto the path, the arrows follow it and the outline re-fits around a row instead of a column – because the layout is solved again, not nudged. hide direct takes the bypassed arrow away in the same beat. Without it, that arrow stays on the drawing and its label is left sitting across the proxy that has moved into its path. And move takes to for one element or by for a set: move @tag to … is refused, because it would stack the whole set on one point.

What print gets is the last beat without the emphasis – not the union of all of them. Everything shown and never hidden is in the last beat anyway, so the two readings differ only where the author wrote hide, and there the last beat is the one that means “the finished picture”. That is also what a reader with no JavaScript sees: the drawing as written into the file already stands at its last beat. On screen the frame is wider – wide enough to hold every beat – or an element walking in from outside it would be clipped for the whole of its journey.

the order, and the walls

A figure with steps is an argument, not a slideshow

The beats are the order the argument is made in, not a way to reveal a picture slowly. This order works almost every time.

beat 1

The stage

Everything that is just true: the topology, the axes, the participants. One beat, no emphasis.

beat 2

The normal case

What happens when nothing is wrong. This is what the attack will be measured against.

beat 3

The disturbance

The attacker, the failure, the exception. This is the beat that earns .accent and emph.

beat 4

The consequence

The defence, the result, the number. Often calm on what came before, so the last beat is not four things shouting at once.

The last beat is what a printed handout gets, so it has to be a picture that makes sense on paper, standing alone. If it is not, you have one beat too few. Going backwards costs nothing either, because every beat is worked out from scratch – which is what makes hide as usable as show.

before a figure is finished

Ten things, checkable mechanically

  1. node lint.js <source.md> reports nothing. A warning you have decided to live with still counts as unclean.
  2. node build.js <source.md> prints no [diagram] warning, or the source carries a comment saying why the remaining one is deliberate.
  3. No edge runs at a slight angle. The build says so; do not silence it by nudging – align the elements.
  4. Every label that overlaps a line or a filled shape has a fill class of its own.
  5. Every arrowhead lands on a border, none inside a box, none two-on-a-line.
  6. No tone carries two meanings in one figure, and none contradicts the table in rule 4.
  7. Each beat is one idea. Read the step names out loud in order: they should sound like an argument.
  8. The last beat is a sensible handout picture on its own.
  9. Opened in the browser and cycled through all seven colour themes with the A key: nothing disappears, nothing becomes unreadable. The two single-colour terminal themes are the hardest to pass.
  10. node test/run.mjs framing passes. It measures the slack on all four sides of every figure, and it is the only check that catches a picture which is correct but not centred in its own frame.

what it cannot do

Eight things the language will not do

No free colours

Four tones, plus .accent and .muted. If you need a fifth distinction, use shape (.hex, .chevron, .wedge, .cross, aimed with point) or family (.mono, .serif) – and ask first whether the figure is doing too much.

No automatic routing

Edges are straight segments through the waypoints you write. Nothing steps around a box for you, and nothing fans out parallel edges – that is what the :0.3 / :0.7 fractions are for.

No automatic line breaking

A label breaks where you write \n, and nowhere else.

No shadows, no gradients, and a fixed drawing order

A shape is a flat outline with a flat fill. What covers what is decided for you too: containers, images, braces, edges, then boxes, dots and texts. The one way out is .front, which moves an edge in front of the boxes – right for an axis, wrong for an arrow, so you have to ask for it.

No arbitrary rotation

.turn turns a label 90°, and point aims a chevron or a wedge at one of the four compass directions. Nothing rotates to an arbitrary angle.

No cylinder, no cloud

The outlines are the rectangle, the circle, the hexagon, the two chevrons and the wedge. A database is a .round box in the tone you gave storage; a cloud is a box labelled Internet. If a shape genuinely carries meaning of its own, draw it as an SVG file and place it with image.

Text width is estimated

There is no browser at build time, so the estimate is tuned slightly generous – a box a little wider than its text reads as designed, a box narrower reads as broken. Where it matters, give an explicit w.

No constraint solver

Every position is written in terms of another position, and the build resolves them in one pass, following the chain. An arrangement that refers back to itself is reported as an error naming the line, rather than drawn as a picture that looks plausible and is wrong.

beyond the basics

Five more things you can write

Four outlines that are not rectangles, a label that reads bottom to top, a bar chart, a plot with a curve through it, and one drawing reused many times over. None of them is a new kind of element: a hexagon is the four numbers a rectangle already carries, drawn as a different outline; a sideways label is a position plus an angle; a curve runs through the same points a straight line would have used. That is why all of them animate between beats with no extra machinery.

Each pair below is real: the drawing was produced by the source shown with it.

Four outlines that are not rectangles, two of which can be aimed

A protocol message that is an arrow, a sensor that is a hexagon, a size comparison that is a triangle, a scatter marker. They share one class group with .round and .sharp, because a hexagon has no corner radius to argue about.

Which way a point aims is set by the point option – up, down, left or right – rather than by a class of its own, so the two pointed outlines cover eight orientations between them. Writing point on an outline that has no point is an error rather than a class that quietly does nothing.

box a "SYN seq=c"       at 0,0 {.chevron .tone-3}
box b "SYN+ACK ack=c+1" below a point left {.chevron}
box c "IDS"             right of a {.hex .tone-1}
box d ""                below c {.wedge .tone-4}
box e ""                right of d point up {.wedge}
box f ""                right of e {.cross .accent}

A label that reads bottom to top

A tall narrow element has room for a word only along its long side. The angle is stored with the label’s position, so a turned label moves and animates between beats exactly as an upright one does.

box  fw "FIREWALL" at 0,0 h 1.5 {.tone-4 .turn}
box  sw "SWITCH"   right of fw gap 0.7
edge fw -> sw.left
text ax "True Positive Rate" left of fw {.turn}

A chart that is still boxes

As the source is read, bars turns into ordinary boxes named f-0, f-1, f-2. A chart is therefore not a new kind of element, which is why a brace can span three of its columns with exactly the syntax it would use on any three boxes.

The baseline carries .front. Drawing order puts edges before boxes, which is right for an arrow – a box should cover the line arriving at it – and wrong for an axis, which came out hidden behind every column and visible only in the gaps.

bars  f "20,19,17,12,11,10,9,9,8,7,6,5"
        ". i e 0 l o 1 / a 3 5 M" at 0,0 w 2 h 0.9
brace b1 over f-0,f-1,f-2 bottom "Bin 1"
brace b2 over f-3,f-4,f-5,f-6,f-7 bottom "Bin 2"

A frame to draw in, and a line through its points

roc@0.35 names a value in the plot’s own units – 0.35 along its axis, not a distance on the page. Once the block has been read that becomes an ordinary offset from the frame’s edge, so a plot coordinate can be written anywhere a position is allowed. .smooth draws a curve that passes through every waypoint, so switching it on never moves a line off the points you attached it to.

plot roc "False positive rate" "True positive rate"
     at 0,0 w 1.8 h 1.4 x 0,1 y 0,1 step 0.2
edge roc@0,roc@0 -> roc@1,roc@1 {.muted .dashed}
edge roc@0,roc@0 -> roc@1,roc@1 via roc@0.03,roc@0.45
     roc@0.1,roc@0.72 roc@0.3,roc@0.9 {.smooth .accent}
dot  m1 at roc@0.1,roc@0.72 {.accent}
box  m2 "" at roc@0.35,roc@0.95 {.cross .tone-3}

One drawing, however often it appears

An image statement places a drawing from an SVG file, and a grid repeats it – twenty-four copies here, from one file. However often a drawing appears, the file is embedded once: the last figure in the gallery below draws ninety-six faces out of two files. The exception is a file carrying its own stylesheet, which has to be embedded once per copy, because that stylesheet does not reach into a shared one and the drawing would arrive with no lines.

grid g image face-ok 8x3 at 0,0 cell 0.26 space 0.09
text n "one file, twenty-four times" right of g
