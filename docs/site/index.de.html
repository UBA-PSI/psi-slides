psi-slides · Präsentationssoftware für Lehrende

Folien, Notizen und Handouts aus einer Datei.

Eine Markdown-Datei wird zu vier in sich geschlossenen HTML-Dateien: der Projektion für den Raum, einem Presenter-Cockpit auf dem eigenen Bildschirm und zwei Handouts – dem Skript allein und dem Skript mit den eigenen Notizen.

Alle vier entstehen aus derselben Quelle. Sie können nicht auseinanderlaufen, weil es nichts gibt, was man synchron halten müsste.

Wie viel Text auf eine Folie passt, gibt das Format vor. Für die Stunde im Hörsaal ist einiges eingebaut: Übersichtstafel, Volltextsuche, Live-Annotationen, Syntaxhervorhebung, LaTeX-Formeln, Video, QR-Codes für jeden Link, eine Uhr und sieben Farbschemata. Kein Server, keine Laufzeitumgebung, keine Cloud.

Loslegen Eine Vorlesung öffnen

Dieselben vier Absätze, einmal geschrieben. Zwischen den ersten beiden Bildern liegt ein Tastendruck – und das dritte ist eine andere Datei aus derselben Quelle: der Schalter zeigen: am Bildschirm / gedruckt in der rechten Leiste wechselt zu ihr. Ein Klick auf ein Bild öffnet es in voller Größe.

Jede Vorlesung besteht aus drei Sorten Text

Da ist der Text, der auf die Folie kommt, knapp genug, dass man ihn aus der letzten Reihe lesen kann. Da ist das Skript – die Sätze, die die Sache wirklich erklären und die in ein Handout gehören statt an die Wand. Und da sind die Notizen für einen selbst: erst die Gruppe fragen; das hier weglassen, wenn die Zeit knapp wird; das geht nicht raus.

Die gängigen Programme, die zum Präsentieren verwendet werden, bieten Folien und ein Notizfeld. Das Skript – der Teil, den Studierende am meisten wollen – bekommt deshalb nie eine eigene Datei. Man behält es im Kopf oder in einem zweiten Dokument, das vom ersten abweicht, sobald man eines von beiden ändert.

Mit psi-slides schreibt man jeden Absatz einmal und markiert den Satz, der ihn trägt. Die Präsentation bekommt nur diesen Satz, das Handout bekommt alles, und die Zeilen hinter > note: bleiben auf dem eigenen Bildschirm.

Was es tut

Die Bilder oben und unten zeigen alle dieselbe Folie einer echten Vorlesung – einer Python-Einführung aus 36 Chunks – und das hier ist das Markdown, in dem sie steht. Zwei der vier Absätze sind gekürzt, damit der Ausschnitt auf diese Seite passt; die Vorlesung selbst ist auf Englisch.

## free: Why Playwright | the modern web is rendered, not served {.wide #why-playwright}

::: cols 2

**A lot of the web is rendered by JavaScript in the browser.**
**`requests` and plain `urllib` see only the HTML shell** – often just
`<div id="app"></div>` plus a pile of script tags. Useful text, links, and
titles never arrive.

**Playwright drives a real browser** – Chromium, Firefox, or WebKit – over a
debugging protocol. The page renders, scripts execute, the DOM settles, and
then you query it. You see what a human sees.

Selbst öffnen

Hier liegen drei Vorlesungen. python-intro ist die von oben. Das Tutorial ist eine selbstbezügliche Tour, die das Werkzeug erklärt, indem sie es benutzt. Beide sind auf Englisch. Das Kurzbeispiel ist ein Ausschnitt aus einer Netzwerk-Vorlesung im ersten Semester, auf Deutsch: 80 Zeilen Markdown, kurz genug, um sie ganz zu lesen und daneben zu sehen, was daraus wird (Quelle, gesetzt nach den Vorlesungsnotizen unter CC BY-NC-SA 4.0).

Am besten mit der Projektion anfangen. Pfeiltasten blättern, Leertaste blendet den nächsten Abschnitt ein, C schaltet die Kürzung um, O (der Buchstabe, nicht die Null) öffnet die Übersichtstafel, / sucht, ? listet alles auf. Wer das Cockpit über den Link hier öffnet, sieht zwar das Layout, aber es ist mit nichts verbunden; ein verbundenes Cockpit öffnet S in der Projektion.

Alle vier Dateien sind in sich geschlossen: CSS, JavaScript, Bilder, die gesetzten Formeln und die Schriften stecken darin. Zur Laufzeit wird nichts nachgeladen, und sie lassen sich von file:// genauso öffnen wie von diesem Server.

Loslegen

Man braucht Node 20 oder neuer, sonst nichts: kein LaTeX, kein Pandoc, keinen Server, nichts global Installiertes. Release herunterladen, auspacken, Tutorial bauen:

# das aktuelle Release, ausgepackt nach psi-slides/
curl -L https://github.com/UBA-PSI/psi-slides/releases/latest/download/psi-slides.tar.gz \
  | tar xz
cd psi-slides

# die mitgelieferten Schriften und die wenigen Pakete, die der Bau braucht
npm install

# alle vier Ansichten neben source.md bauen, dann die Projektion öffnen
node build.js lectures/tutorial/source.md
open lectures/tutorial/audience.html   # macOS; sonst xdg-open oder der Browser

Unter Windows das .zip von derselben Release-Seite nehmen. Ein git clone des Repositorys funktioniert genauso – das Archiv ist derselbe Baum ohne die Historie.

Das baut das Tutorial: eine Vorlesung, die das Werkzeug erklärt, indem sie es benutzt. ? zeigt die Tastenübersicht, S öffnet das Cockpit. Seine source.md ist die Referenz fürs Schreiben, und die vier erzeugten Dateien kann man verschieben, mailen oder hochladen – sie tragen alles bei sich, was sie brauchen.

Dann die eigene schreiben

# ein Verzeichnis mit gültigem Frontmatter anlegen
node build.js --new my-lecture

# bei jedem Speichern neu bauen und alle offenen Tabs neu laden
node build.js lectures/my-lecture/source.md --watch

# Chunk-IDs, Wortbudgets, offene Direktiven, zu große Assets
node lint.js lectures/my-lecture/source.md

Editor, Projektion und Cockpit nebeneinander offen halten: --watch baut bei jedem Speichern neu und lädt die beiden Browserfenster sofort nach. Am Ende sind die vier HTML-Dateien neben der source.md das Ergebnis. Mehr muss nicht mitreisen.
